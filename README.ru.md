# SpaceCopVPN

**Собственный, децентрализованный VPN-протокол с системой поощрения узлов, написанный с нуля.**
Без OpenVPN, без WireGuard, без сторонних сетевых и криптографических библиотек:
протокол, разбиение пакетов, оверлейная сеть узлов, реестр очков и даже
криптографические примитивы реализованы напрямую поверх стандартной
библиотеки Python.

> **Назначение.** Это проект приватной сети для обучения и экспериментов — в том
> же духе, что открытые WireGuard, Tor и стимулируемые mesh-сети (Mysterium,
> Orchid, Sentinel). Криптографические примитивы — точные реализации
> опубликованных, проверенных стандартов (ChaCha20-Poly1305, X25519, Ed25519,
> HKDF), сверенные с тестовыми векторами RFC и с OpenSSL. Придумывать
> собственную криптографию безответственно, поэтому *алгоритмы* стандартные,
> а *код* написан здесь по их спецификациям. Модель безопасности и её границы —
> в [docs/ru/ARCHITECTURE.md](docs/ru/ARCHITECTURE.md); перед применением там,
> где от этого зависит реальная безопасность, такой стек нужно аудировать.

## Что умеет

* **Собственный протокол** — датаграммы с 4-байтовым заголовком и версией,
  аутентифицированное рукопожатие с прямой секретностью (Noise-подобный
  паттерн `e, es, ee`), отдельные ключи на каждое направление, монотонные
  nonce и защита от повторов скользящим окном.
* **Кроссплатформенность** — ядро на чистой стандартной библиотеке Python 3.8+,
  работает без изменений на Windows, Linux и Android. Для устройства есть
  бэкенд Linux `/dev/net/tun`, бэкенд Android `VpnService` (через файловый
  дескриптор), инструкция для Windows/Wintun и **SOCKS5-прокси без драйверов и
  root**, который работает везде.
* **Децентрализация** — узлы находят друг друга через gossip подписанных
  анонсов от небольшого стартового списка; центрального сервера нет. Клиент
  подключается сразу ко многим узлам.
* **Узлы конкурируют и зарабатывают очки** — как майнеры, тратящие дефицитный
  ресурс (здесь — реальную полосу и аптайм), узлы соревнуются за ретрансляцию
  трафика. За каждую ретрансляцию клиент выдаёт подписанную проверяемую
  **квитанцию proof-of-relay**; реестр считает очки и строит рейтинг. Регистрация
  узла защищена **proof-of-work** в стиле hashcash от Sybil-атак.
* **Фрагменты по 20 КБ в случайном порядке, все зашифрованы** — любая полезная
  нагрузка (в обе стороны) режется на фрагменты по 20 КБ, отправляется в
  перемешанном порядке, каждый фрагмент шифруется отдельно и собирается на
  принимающем устройстве.
* **Настоящие TCP-потоки: HTTPS просто работает** — SOCKS5-прокси несёт каждое
  соединение как поток (маленький TCP-подобный движок поверх зашифрованных
  датаграмм: чанки под MTU, окно, выборочные подтверждения, повторная
  отправка), поэтому TLS-рукопожатия, keep-alive, WebSocket и SSH проходят.
  Проверено живым HTTPS-запросом через `curl --socks5-hostname`.
* **Постоянный IP на одном сайте** — все запросы к одному сайту (включая его
  поддомены) идут через один и тот же выходной узел в рамках сессии, поэтому
  сайт видит один стабильный IP и не сбрасывает авторизацию.
* **Тысячи параллельных запросов** — узел выполняет ретрансляции в пуле
  рабочих потоков, потерянные фрагменты досылаются повторно, а ответы
  кэшируются, чтобы повтор не обращался к сайту дважды.
* **Графический клиент** — окно на Tkinter: профили, вставка строки
  подключения `spacecop://…`, запуск SOCKS5, тест, таблица здоровья узлов. Пакет
  для **Arch Linux** и скрипт установки на любой сервер.

## Быстрый старт

Всё работает на loopback без прав администратора. Запустите демо:

```
python examples/local_demo.py
```

Оно поднимает эхо-сервер, четыре конкурирующих узла и клиента, отправляет 40
фрагментированных зашифрованных запросов, распределяя их по узлам, и печатает
таблицу очков и рейтинг узлов по задержке.

### Сервер (узел) — одна команда на любом Linux

```
sudo ./deploy/install_server.sh
```

Скрипт ставит python3, копирует проект в `/opt/spacecop`, создаёт постоянную
идентичность узла в `/etc/spacecop/identity.json`, регистрирует службу systemd
`spacecop-node`, открывает UDP-порт в ufw/firewalld и печатает **строку
подключения** вида:

```
spacecop://203.0.113.9:51820/<x25519-ключ>/<ed25519-идентификатор>
```

### Клиент с интерфейсом (Arch Linux)

```
./packaging/install_client_arch.sh      # соберёт и установит пакет; или --user
spacecop-gui                             # либо «SpaceCopVPN» в меню приложений
```

Вставьте строку подключения → «Добавить узел» → «Подключиться». Локальный
SOCKS5-прокси (по умолчанию `127.0.0.1:1080`) укажите в браузере или системе.
Подробно: [docs/ru/INSTALL.md](docs/ru/INSTALL.md).

### Из командной строки

```
python -m spacecop.cli keygen --identity id.json --host <ip>   # ключи + URI узла
python -m spacecop.cli node --port 51820 --advertise <ip> --identity id.json
python -m spacecop.cli proxy --uri spacecop://... --listen 127.0.0.1:1080
python -m spacecop.cli relay --uri spacecop://... --dest example.com:80
python -m spacecop.cli gui
```

## Тесты

```
python -m unittest discover -s tests -p 'test_*.py'
```

89 тестов: криптография по векторам RFC 8439/7748/5869 и OpenSSL, рукопожатие и
сессии, защита от повторов, фрагментация и сборка, реестр очков и proof-of-work,
строки подключения и сохранение идентичности, сквозная ретрансляция по
настоящим UDP/TCP-сокетам, потоки (многошаговые диалоги, передача 700 КБ, 120
параллельных соединений, канал с 30% потерь, SOCKS5), 300 параллельных
запросов под нагрузкой, «один сайт — один узел» и диагностика ping/рукопожатия.

## Структура

```
spacecop/
  crypto/         ChaCha20, Poly1305, AEAD, X25519, Ed25519, HKDF
  protocol/       константы, кадрирование, рукопожатие, сессия, сообщения, URI
  fragmentation/  фрагментер 20 КБ с перемешиванием + сборщик
  transport/      UDP-транспорт
  node/           узел-ретранслятор, каталог пиров (gossip), реестр очков, PoW
  client/         клиент + выбор узлов с «липкой» привязкой к сайту
  tun/            Linux TUN, Android fd, Windows/Wintun, SOCKS5-прокси
  gui/            графический клиент (Tkinter)
  cli.py          команды keygen / uri / node / proxy / relay / gui
deploy/           install_server.sh — установка узла на любой сервер
packaging/        PKGBUILD для Arch, .desktop, install_client_arch.sh
examples/         local_demo.py, run_node.py, run_client.py
docs/ru/          документация на русском (и docs/ — на английском)
tests/            тесты
```
