# Протокол SpaceCopVPN (формат «на проводе»)

Версия 1. Все многобайтовые числа — **big-endian**, если не сказано иное.

## 1. Заголовок кадра

Каждая UDP-датаграмма начинается с фиксированного 4-байтового заголовка:

```
+--------+--------+---------+----------+
| 'S'    | 'C'    | версия  | тип      |
| 0x53   | 0x43   | 1 байт  | 1 байт   |
+--------+--------+---------+----------+
```

* `magic` = `b"SC"` — дешёвое отбрасывание чужого трафика.
* `version` = `1`.
* `msg_type` — код из §2. Остаток датаграммы — **тело** сообщения, формат
  которого зависит от типа.

## 2. Типы сообщений

| Код    | Имя              | Направление      | Назначение                                |
|--------|------------------|------------------|-------------------------------------------|
| `0x01` | HANDSHAKE_INIT   | клиент → узел    | начать сессию                             |
| `0x02` | HANDSHAKE_RESP   | узел → клиент    | завершить сессию                          |
| `0x03` | DATA             | оба              | один зашифрованный фрагмент               |
| `0x04` | ACK              | оба              | подтверждение индексов фрагментов         |
| `0x05` | PING             | оба              | проверка живости                          |
| `0x06` | PONG             | оба              | ответ на PING                             |
| `0x10` | NODE_ANNOUNCE    | узел → сеть      | подписанный самоанонс                     |
| `0x11` | PEER_REQUEST     | оба              | запрос известных пиров                    |
| `0x12` | PEER_LIST        | оба              | список известных пиров                    |
| `0x20` | RELAY_REQUEST    | клиент → узел    | переслать непрозрачный блок адресату      |
| `0x21` | RECEIPT          | клиент → узел    | подписанная квитанция proof-of-relay      |
| `0x22` | SCORE_QUERY      | оба              | запрос очков узла                         |
| `0x23` | SCORE_REPORT     | узел → спросившему | отчёт о накопленных очках               |
| `0x24` | RELAY_RESPONSE   | узел → клиент    | ответ адресата                            |

## 3. Кодирование полей

* `u8/u16/u32/u64` — целые фиксированной ширины, big-endian.
* `bytes16` — 2-байтовый префикс длины и столько байт.
* `bytes32` — 4-байтовый префикс длины (для больших полей).

## 4. Рукопожатие

Собственный Noise-подобный обмен. Клиент заранее знает статический ключ
X25519 узла `S` (из подписанного `NODE_ANNOUNCE` или строки подключения).

**Тело HANDSHAKE_INIT** (48 байт):

```
session_id : 8 байт (случайные, выбирает клиент)
e_c_pub    : 32 байта (эфемерный публичный ключ X25519 клиента)
timestamp  : u64 (unix-секунды; отклоняется при расхождении > 120 с)
```

Узел создаёт свой эфемерный ключ `e_n` и вычисляет два общих секрета:

```
ss_static = X25519(node_static_priv, e_c_pub)     # аутентифицирует узел
ss_eph    = X25519(e_n_priv,        e_c_pub)       # прямая секретность
transcript = SHA256(MAGIC || VERSION || session_id || e_c_pub || e_n_pub || S)
PRK        = HKDF-Extract(salt = transcript, IKM = ss_static || ss_eph)
k_c2n || k_n2c || k_confirm = HKDF-Expand(PRK, "spacecop/v1 session-keys", 96)
```

Если любой из секретов равен нулю (пир прислал точку малого порядка,
RFC 7748 §6.1), рукопожатие отклоняется.

**Тело HANDSHAKE_RESP**:

```
session_id : 8 байт (эхо)
e_n_pub    : 32 байта (эфемерный публичный ключ X25519 узла)
sealed     : ChaCha20-Poly1305( key = k_confirm, nonce = 0,
                                 aad = transcript,
                                 plaintext = node_ed_pub(32) || Ed25519_sig(64) )
```

Подпись — над `transcript`; она привязывает Ed25519-идентичность узла к обмену
ключами. Клиент вычисляет те же секреты, открывает `sealed`, проверяет подпись
(и совпадение с ожидаемой идентичностью, если она была задана).

Итог: клиент шифрует ключом `k_c2n`, расшифровывает `k_n2c`; узел — наоборот.
`k_confirm` используется только для ответа, поэтому счётчики данных начинаются
с 0. Клиент не предъявляет долговременной идентичности (анонимный клиент).

## 5. Записи сессии (DATA)

У каждого направления свой 64-битный счётчик, он же nonce. Запечатанная запись:

```
counter : u64
ct||tag : ChaCha20-Poly1305( key = ключ направления,
                             nonce = 0x00000000 || counter,
                             aad = <aad вызывающего> || counter,
                             plaintext = <байты фрагмента> )
```

**Тело DATA** = `session_id(8) || sealed_record`. Получатель находит сессию по
`session_id`, расшифровывает и проверяет счётчик по скользящему окну на 1024
записи (новее окна — принимается; в окне — отклоняется, если уже видели; старше
окна — отклоняется).

## 6. Фрагментация

Открытый текст внутри записи сессии — **фрагмент**:

```
group_id : u32 (случайный на каждое логическое сообщение)
count    : u32 (всего фрагментов в группе)
index    : u32 (0 .. count-1)
payload  : до 20480 байт (FRAGMENT_SIZE)
```

Логическое сообщение приложения (само по себе полный кадр, например
RELAY_REQUEST) режется на `count` фрагментов ≤ 20 КБ, **перемешивается**, и
каждый фрагмент запечатывается отдельно. Получатель группирует по `group_id`,
игнорирует дубликаты и, собрав все `count` индексов, склеивает их по порядку.
Незавершённые группы истекают через 30 с; число групп в полёте ограничено.

## 7. Ретрансляция

Передаётся как сообщение приложения *внутри* зашифрованной сессии (узел видит
только шифртекст, пока не соберёт полный запрос):

**Тело RELAY_REQUEST**: `request_id(bytes16) || dest_host(bytes16) ||
dest_port(u16) || blob(bytes32)`. Узел открывает TCP-соединение к
`(dest_host, dest_port)`, отправляет `blob`, читает ответ (с ограничениями по
времени и размеру) и возвращает:

**Тело RELAY_RESPONSE**: `request_id(bytes16) || status(u8) || blob(bytes32)`,
`status = 0` при успехе.

Повторная отправка: если клиент не получил ответ, он досылает **те же самые**
запечатанные фрагменты (окно повторов отбросит уже виденные, сборщик
проигнорирует дубликаты). Узел помнит готовые ответы по `(session_id,
request_id)` в течение 60 с и на повтор отвечает из кэша, не обращаясь к
адресату второй раз.

## 8. Обнаружение

**Тело NODE_ANNOUNCE**: `ed_pub(32) || x_pub(32) || host(bytes16) || port(u16) ||
score(u64) || timestamp(u64) || signature(bytes16)`, подпись Ed25519 над всем,
что до неё. **Тело PEER_LIST**: `count(u16)`, затем `count` ×
`{ed_pub(32) || x_pub(32) || host(bytes16) || port(u16)}`. На PEER_REQUEST узел
отвечает списком пиров и своим анонсом.

## 9. Квитанции

**Тело RECEIPT**: `client_ed_pub(32) || node_ed_pub(32) || seq(u64) ||
byte_count(u64) || timestamp(u64) || signature(bytes16)`, подпись Ed25519
клиента над всем, что до неё. См. [SCORING.md](SCORING.md).

## 10. Строка подключения

```
spacecop://<host>:<port>/<x25519_pub_hex>[/<ed25519_pub_hex>]
```

Одна строка полностью описывает узел; её печатает узел при запуске и скрипт
установки сервера. IPv6-адрес записывается в квадратных скобках.
